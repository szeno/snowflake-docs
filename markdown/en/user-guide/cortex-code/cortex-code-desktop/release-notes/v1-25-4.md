# CoCo Desktop v1.25.4 release notes

In v1.25.4, the agent’s browser tools act only on the browser panel of the chat that called them, artifacts open in the **Files** preview, the Project Action Bar is the only dbt view, dbt projects are found faster, and Windows updates install only when Snowflake signed them.

## What’s new

- **Browser tools stay with their chat**: Each chat has its own browser panel, and the agent’s browser tools act on the panel of the chat that called them. Previously, if you switched chats while an agent was using the browser, its clicks and page reads could go to the other chat’s browser. For what the agent can do in a browser panel that isn’t on screen, see [Known limitations](#known-limitations).
- **Back and forward in Agent view**: Press **⌘[** and **⌘]** (**Ctrl+[** and **Ctrl+]** on Windows) to go back and forward in Agent view. These shortcuts replace **Ctrl+-** and **Ctrl+Shift+-** on macOS and **Alt+Left Arrow** and **Alt+Right Arrow** on Windows. Editor view is unchanged.
- **Horizontal scrolling with a mouse wheel**: In Agent view, a mouse wheel scrolls the terminal panel’s tabs sideways.
- **Sessions open on the first click**: In the Agent view sidebar, a running session now opens on the first click. Previously, a click could be lost while the session’s row updated.
- **Artifacts open in the Files preview**: When you select a Snowflake artifact in a chat, CoCo Desktop opens a copy in the **Files** preview, including artifacts that others shared with you. The copy is stored in CoCo Desktop’s data folder, not in your project, and CoCo Desktop checks your access each time you open it. To open artifacts on the **Artifacts** page instead, disable the `chat.artifacts.previewDownload.enabled` setting.
- **Project Action Bar is the only dbt view**: The previous dbt view and the `dbt.redesign` setting are removed.
- **Faster dbt project discovery**: CoCo Desktop now finds `dbt_project.yml` files with a single ripgrep file search instead of opening every folder in the workspace one at a time. In large workspaces, such as monorepos, the dbt project list appears much sooner. Discovery finds the same projects as before and still honors the `dbt.allowListFolders` setting. If the search can’t run, CoCo Desktop falls back to scanning folders.

## Reliability and fixes

- **Signed Windows updates**: On Windows, CoCo Desktop installs an update only if its Authenticode signature is valid and was issued to Snowflake Inc. The check applies to updates that you install from v1.25.4 onward.
- **dbt project paths are checked before local runs**: Local runs from the Project Action Bar, the editor title bar, and the command box refuse to start when `dbt_project.yml` or a `--project-dir`, `--profiles-dir`, `--target-path`, or `--log-path` flag points outside the project. The output shows **Refusing to invoke dbt:** and the reason.
- **dbt not found on Windows**: When `dbt` isn’t on your `PATH`, a local dbt run on Windows now shows the **dbt was not found** guidance, instead of reporting a failed dbt command.
- **Execution mode during a dbt run**: The dbt execution mode can no longer be switched while a run from the Project Action Bar is in progress.

## Known limitations

The agentic browser has these limitations in v1.25.4:

- **Clicks and screenshots need a browser panel on screen**: The agent can click, press keys, drag, and take screenshots only in a browser panel that’s on screen. When a chat’s browser panel isn’t shown, for example because you switched to another chat or closed the panel, those actions fail and the agent asks you to switch to that chat and open its browser panel. The agent can still read the page, navigate, go back and forward, and run scripts on the page.
- **Several sessions using the browser at once**: Only the chat that you’re viewing can interact with its browser page. If you run several sessions that use the browser at the same time, the sessions that you aren’t viewing stop at their next click, key press, drag, or screenshot and wait for you to switch to them. For browser tasks such as testing an app, stay on that chat until the agent finishes, or run them one chat at a time.
- **Pages opened from a chat that you aren’t viewing**: If the agent opens a page in a chat whose browser panel hasn’t opened yet, the page opens when you return to that chat. Until then, the agent can’t read the page.

For more information, see [Browsers in multiple chats](/user-guide/cortex-code/cortex-code-desktop/agentic-browser#label-cortex-code-desktop-agentic-browser-multiple-chats).
