# CoCo Desktop v1.23.0 release notes

v1.23.0 makes the session list easier to organize, keeps prompt history with the chat it came from, and brings Snowflake Managed MCP servers to all accounts. It also fixes dbt Show for dbt Fusion projects that use dbt State, and syncs more of your dbt project to Snowflake-managed runs.

## What’s new

- **Organize the session list**: The session list in the Agent view now includes an **Automations** section, a count of sessions that need your attention on each section, and a **Customize sessions list** menu. Use **Grouping** to group sessions by **Date** or **Status**, and **Ordering** to sort them by **Recent** or **Status**. Your choices are kept between restarts. These options were previously behind an experimental setting and are now available to everyone.
- **Copy a session’s ID or transcript**: Right-click a session in the session list and choose **Copy** > **Copy Session ID** or **Copy Transcript**.
- **Prompt history for each chat**: Pressing the Up and Down arrow keys in the message box now steps through the messages you sent in the current chat, newest first, including messages you queued or used to steer the agent. Previously, the history was shared by every chat in the workspace. A chat with no messages yet still uses the workspace history.
- **Snowflake Managed MCP servers for all accounts**: CoCo Desktop discovers MCP servers that your administrator enabled in Tools for every account, and lists them under **Agent Settings** > **MCP** > **Snowflake Managed**. On accounts where the feature isn’t available, the tab reads “Not available on this account.” To turn off discovery, disable the `snowflake.mcp.managedServers.enabled` setting. See [MCP support](/user-guide/cortex-code/cortex-code-desktop/mcp-support).
- **Notifications open their chat**: Operating system notifications for approvals and responses are now titled with the name of their chat. Clicking a notification opens that chat, even when it isn’t the chat you have open.
- **Restricted session scopes for email-style usernames**: You can now apply a named restricted session scope from a personal database whose username contains punctuation, such as `"USER$FIRST.LAST@EXAMPLE.COM".RSS.MY_SCOPE`.

## Reliability and fixes

- **dbt Show works with dbt Fusion and dbt State**: On a local dbt Fusion installation with dbt State enabled, **Show** no longer reports a successful run as failed with empty results. The rows appear in SQL Results.
- **More of your dbt project syncs to Snowflake-managed runs**: Snowflake-managed dbt runs now upload files under `functions/`, `OSI/`, `checks/`, and `skills/` (or the paths set in `dbt_project.yml`), and under `docs-paths` and `asset-paths` when you set them. Models that call a user-defined function no longer fail because the function file wasn’t synced. Files matched by `.dbtignore` and dotfiles such as `models/.env` are no longer uploaded, and a project without a `tests/` or `seeds/` folder syncs normally.
- **Clearer errors when sharing or installing skills**: When the stage’s cloud storage returns an unreadable error response, sharing or installing a skill now shows a message that the problem is usually temporary and to try again in a few minutes, instead of raw driver output.
- **Background subagent edits are applied**: File edits from a background subagent that finish after the turn that started it has ended are now applied instead of failing.
- **Readable Open in Finder button in light themes**: In the files panel, the **Open in Finder** (or **Open in File Explorer**) button shown when a file can’t be loaded is readable in light themes.
