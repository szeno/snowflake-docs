# CoCo Desktop v2.1.0 release notes

CoCo Desktop v2.1.0 lets the agent move into Plan mode without stopping to ask, and lets you choose the model and effort that each subagent runs on. The Agentic Browser sends the model less to read after each action, and Snowflake object discovery searches every object type at once. This release also fixes SQL failures after a session expires, failed requests on slow connections, and missing results in the dbt **Lineage** panel.

## What’s new

- **Plan mode without a confirmation**: When the agent decides a task needs a plan, it switches to [Plan mode](/user-guide/cortex-code/cortex-code-desktop/agent-mode-and-plan-mode) right away instead of showing a confirmation dialog. You still review and approve the plan before any code is written, and switching back to Agent mode still asks first.
- **Model and effort for each subagent**: The agent can choose the model and effort that a [subagent](/user-guide/cortex-code/cortex-code-desktop/agents) runs on, including **inherit** to match the main chat or **auto** to let CoCo pick. A subagent’s chat has its own model and effort pickers, so you can change one subagent without changing your defaults, and its header shows the model and effort it runs on.
- **Lighter Agentic Browser**: Screenshots that the [Agentic Browser](/user-guide/cortex-code/cortex-code-desktop/agentic-browser) takes are sized to the page rather than to your display’s pixel density, so they are a quarter of the size on a high-resolution display. After an action such as a click or typing, the agent gets a short summary instead of the whole page, and reads the page again only when it needs to.
- **Waiting on background commands**: When the agent starts a long-running command in the background, it can wait for the command to finish and see its exit status, instead of checking its output again and again.
- **Broader Snowflake object discovery**: When you ask for an object by name without saying what kind of object it is, the `snowflake-object-discovery` subagent searches every object type in one step, so it no longer misses less common types such as application services. When you ask for an existing asset, such as a dashboard, it looks for the matching object type and prefers the original object over a temporary or personal copy.
- **Defer to Production always available**: The `dbt.deferToProduction` setting is removed. **Defer to Production** is always available in the run options for Snowflake-managed dbt runs, and you still turn it on for each project.
- **Managed policies for MCP servers you add**: For organizations that use [managed settings](/user-guide/cortex-code/cortex-code-desktop/managed-settings), a policy that denies `mcp(user:*)` now applies in CoCo Desktop. MCP servers that you add yourself, including servers that come with a plugin, don’t load.

## Reliability and fixes

- **SQL recovers after a session expires**: After a Snowflake session expired, or a proxy refused a request, every later SQL query could fail with **SQL execution returned no query ID and result is unavailable**. CoCo Desktop now shows the actual error, reconnects, and runs the query again.
- **No failed requests on slow connections**: On a slow connection, a request could fail with **could not describe agent profile**. CoCo Desktop now checks your agent profile when it starts, reconnects, or changes connection or role, and when you pick a profile, instead of before every request.
- **dbt Lineage shows results of earlier runs**: If you opened the **Lineage** panel after a dbt run finished, it showed no results for that run. It now shows which models succeeded, failed, or were skipped.
- **dbt Lineage shows results of a Run from the editor title**: In local mode, a dbt run started with the **Run** button in the editor title could show no results in the **Lineage** panel. Results now match the command that the run used.
- **Side panel animation**: Switching between panels such as **Files**, **Terminal**, and **Changes** while the side panel is open no longer replays the panel’s opening animation.
