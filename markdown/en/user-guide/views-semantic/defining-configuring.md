# Defining and configuring semantic views

After you create a [semantic view](/user-guide/views-semantic/overview), refine what it contains and how it behaves
in Semantic Studio or by editing the YAML definition directly. These topics cover the elements you define in a semantic
view and the rules that keep it valid.

- Build and refine a semantic view in Semantic Studio. See [Semantic Studio](/user-guide/views-semantic/semantic-studio).
- Define a logical table from a SQL query instead of a physical table. See [Using an SQL query as a logical table in a semantic view](/user-guide/views-semantic/inline-view).
- Understand the structural and semantic rules a semantic view must satisfy. See
  [How Snowflake validates semantic views](/user-guide/views-semantic/validation-rules).
- Define reusable named filters. See [Defining filters for logical tables in a semantic view](/user-guide/views-semantic/filters).
- Parameterize logic with variables. See [Using variables in a semantic view](/user-guide/views-semantic/variables).
- Materialize dimensions and metrics to improve performance. See [Materializing dimensions and metrics in semantic views](/user-guide/views-semantic/materializations).
