## SQL updates

### IPADDRESS data type (*General availability*)

With this release, Snowflake is pleased to announce the general availability of the `IPADDRESS` data type. An
`IPADDRESS` value stores an IPv4 or IPv6 address as a native 128-bit value. Snowflake validates each address,
stores it in a canonical form, and compares values in numeric address order. Use `TO_IPADDRESS` and
`TRY_TO_IPADDRESS` to convert strings to `IPADDRESS` values, and use `IPADDRESS_TRUNC` to group or match
addresses by network.

With general availability, user-defined functions (UDFs), user-defined table functions (UDTFs), and stored
procedures can accept and return `IPADDRESS` values in every handler language. Java and Scala handlers use
`java.net.InetAddress` or `String`, Python handlers use `ipaddress.IPv6Address`, and JavaScript handlers use
`string`.

For more information, see [IPADDRESS data type](/sql-reference/data-types-ipaddress) and [Data Type Mappings Between SQL and Handler Languages](/developer-guide/udf-stored-procedure-data-type-mapping).

## Improved behavior when dropping application package versions in Native Apps

Starting with this release, commands that drop a version from an application package wait for the operation to
complete before returning a success message. These commands can now take one to two minutes to complete instead
of returning within seconds. When the command succeeds, the version has been fully dropped, so you no longer need
to poll `SHOW VERSIONS` before adding or registering another version.

## Snowflake Cortex updates

### CoCo Admin in Snowsight (*Preview*)

With this release, CoCo Admin in Snowsight is available in public preview. Instead
of a manual checklist of steps, CoCo Admin automatically detects the status of
CoCo enablement on your account and tells you exactly what remaining steps you
need to take to successfully set it up.

From one place, account administrators can configure cross-region inference,
grant user and role access, choose which models can handle requests, and monitor
adoption. Every setting is expressed as SQL, with a SQL preview toggle in each
dialog, so configuration stays transparent and data access is unchanged.

For more information, see [Enable and manage Cortex Code for your account](/user-guide/cortex-code/cortex-code-admin).
