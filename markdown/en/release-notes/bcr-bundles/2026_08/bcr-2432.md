# Legacy SNOWFLAKE.CORTEX functions removed in favor of AI Functions in inactive accounts (Pending)

Attention

This behavior change is in the 2026\_08 bundle.

For the current status of the bundle, refer to [Bundle history](/release-notes/bcr-bundles/2026_08_bundle#label-behavior-change-bundle-2026-08-status).

When the 2026\_08 bundle is enabled, calls to the legacy functions below fail only in accounts marked
inactive. Snowflake does not redirect these calls to the replacement functions.

Before the change:
:   You could call the legacy functions in the `SNOWFLAKE.CORTEX` namespace.

After the change:
:   Snowflake marks an account inactive for this change if it had no usage of any listed legacy function
    from July 9 through October 6, 2026 (the 90-day lookback period). Only accounts marked inactive lose
    access to these functions when the 2026\_08 bundle is enabled.

    Starting to use a legacy function after the 2026\_08 bundle is released does not change the account’s
    inactive classification. When the bundle is enabled, calls to these functions continue to fail for
    that account.

## How to update your code

If an account is marked inactive, update SQL statements, applications, and scheduled workloads that
call these legacy functions before enabling the 2026\_08 bundle. Some replacements change arguments,
error handling, or output format, so the function-name mapping alone might not be sufficient. Review
the [migration guide for legacy Cortex functions](/user-guide/snowflake-cortex/aisql-migrate-legacy-functions)
and test your updated workloads.

For inactive accounts, this change also affects the legacy-function APIs in the `snowflake.cortex.*`
module of the `snowflake-ml-python` package. Upgrade to version `2.4.0` to continue using these APIs
with an updated backend that calls the corresponding AI Functions, or use
`snowflake.snowpark.functions` for AI Function APIs instead.
