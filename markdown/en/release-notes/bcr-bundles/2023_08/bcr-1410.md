# Bind variables: No longer ignored as parameters for some built-in table functions

Attention

This behavior change is in the 2023\_08 bundle.

For the current status of the bundle, refer to [Bundle History](/release-notes/bcr-bundles/2023_08_bundle#label-behavior-change-bundle-2023-08-status).

In [Snowflake Scripting](/developer-guide/snowflake-scripting/index), a [driver](/developer-guide/drivers), or the
[SQL REST API](/developer-guide/sql-api/index), you can use bind variables in SQL statements. (For examples of using bind
variables, see [Using a variable in a SQL statement (binding)](/developer-guide/snowflake-scripting/variables#label-snowscript-variables-binding), [Binding data](/developer-guide/python-connector/python-connector-example#label-python-connector-binding-data), and
[Using bind variables in a statement](/developer-guide/sql-api/submitting-requests#label-sql-api-bind-variables).

This behavior change affects cases in which you pass a bind variable directly as one of the
[built-in table function arguments listed below](/release-notes/bcr-bundles/2023_08/bcr-1410#label-bcr-1410-table-function-args). The behavior changes in the
following way:

Before the change:
:   The bind variable is ignored, and the argument is not passed to the table function.

AFter the change:
:   The bind variable is passed as an argument to the table function.

Note that this does not affect cases in which you pass a bind variable to another function before passing the result to a table
function argument. For example, if you are calling the COPY\_HISTORY function, this change affects cases in which you pass a
bind variable directly as the START\_TIME argument:

Copy code

```
COPY_HISTORY( START_TIME=> ?, ...
```

This does not affect cases in which you pass the bind variable to another built-in function first:

Copy code

```
COPY_HISTORY( START_TIME=> DATEADD('days', ?, ...
```

If you want to preserve the behavior before the change, you can rewrite your code to avoid passing the argument that uses the
bind variable. For example, if you are calling the TASK\_HISTORY function and you do not want the results filtered by a specific
task, omit the TASK\_NAME argument from the call.
