# BACKUP\_OPERATION\_HISTORY views: TIMESTAMP\_LTZ always used for the `start_time` column

Attention

This behavior change is in the 2026\_01 bundle.

For the current status of the bundle, refer to [Bundle history](/release-notes/bcr-bundles/2026_01_bundle#label-behavior-change-bundle-2026-01-status).

In the [ACCOUNT\_USAGE.BACKUP\_OPERATION\_HISTORY](/sql-reference/account-usage/backup_operation_history) and [ORGANIZATION\_USAGE.BACKUP\_OPERATION\_HISTORY](/sql-reference/organization-usage/backup_operation_history) views, the `start_time` column behaves as follows:

Before the change:
:   The `start_time` column has the type [TIMESTAMP\_LTZ](/sql-reference/data-types-datetime#label-datatypes-timestamp-variations) or another type returned by the [TO\_TIMESTAMP](/sql-reference/functions/to_timestamp) function, depending on the value of the [TIMESTAMP\_TYPE\_MAPPING](/sql-reference/parameters#label-timestamp-type-mapping) parameter.

After the change:
:   The `start_time` column will have the type TIMESTAMP\_LTZ, regardless of the setting of the TIMESTAMP\_TYPE\_MAPPING parameter.

This change is being made to ensure consistent behavior across these views and to align with standard Snowflake practices for TIMESTAMP columns in system views.

The `start_time` column in the following deprecated views will also have this change:

- [ACCOUNT\_USAGE.SNAPSHOT\_OPERATION\_HISTORY](/sql-reference/account-usage/snapshot_operation_history)
- [ORGANIZATION\_USAGE.SNAPSHOT\_OPERATION\_HISTORY](/sql-reference/organization-usage/snapshot_operation_history)
