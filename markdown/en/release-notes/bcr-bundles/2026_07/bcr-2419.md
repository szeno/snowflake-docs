# LOGIN\_HISTORY view: User task sessions report authentication\_method as None (Pending)

Attention

This behavior change is in the 2026\_07 bundle.

For the current status of the bundle, refer to [Bundle history](/release-notes/bcr-bundles/2026_07_bundle#label-behavior-change-bundle-2026-07-status).

When this behavior change bundle is enabled, the `authentication_method` column in the
[LOGIN\_HISTORY](/sql-reference/account-usage/login_history) view reports `None` instead of NULL for
sessions created by user tasks.

Before the change:
:   The `authentication_method` column is NULL for user task sessions because these sessions don’t use an
    external authentication mechanism.

After the change:
:   The `authentication_method` column is `None` for user task sessions. This explicitly indicates that
    no authentication method was used, making it easier to distinguish task sessions from rows where the
    value is genuinely unknown.

If you have queries or reports that filter on `authentication_method IS NULL` to identify user task
sessions, update them to filter on `authentication_method = 'None'` instead (or use
`authentication_method IS NULL OR authentication_method = 'None'` during the transition period).

Ref: 2419
