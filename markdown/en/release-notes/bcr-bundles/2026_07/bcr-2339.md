# Access control: DESCRIBE command no longer uses TAG\_ASSOCIATION and GRANT\_MANAGEMENT privileged access operations (Pending)

Attention

This behavior change is in the 2026\_07 bundle.

For the current status of the bundle, refer to [Bundle history](/release-notes/bcr-bundles/2026_07_bundle#label-behavior-change-bundle-2026-07-status).

[DESCRIBE](/sql-reference/sql/desc) commands (for example,
[DESCRIBE TABLE](/sql-reference/sql/desc-table),
[DESCRIBE FUNCTION](/sql-reference/sql/desc-function)) no longer use the
TAG\_ASSOCIATION and GRANT\_MANAGEMENT privileged access operations to resolve objects.

Before the change:
:   The TAG\_ASSOCIATION privileged access operation (associated with the
    [APPLY TAG ON ACCOUNT](/user-guide/security-access-control-privileges#global-privileges) privilege)
    and the GRANT\_MANAGEMENT privileged access operation (associated with the
    [MANAGE GRANTS](/user-guide/security-access-control-privileges#global-privileges) privilege)
    were included as privileged access paths for DESCRIBE commands. This allowed roles with
    MANAGE GRANTS or APPLY TAG ON ACCOUNT to describe objects they otherwise lacked explicit access
    to, as long as the object could be resolved through one of those operations.

After the change:
:   DESCRIBE commands no longer use TAG\_ASSOCIATION or GRANT\_MANAGEMENT as privileged access paths.
    A role must have explicit access to an object (for example,
    [OWNERSHIP, USAGE, or REFERENCES](/user-guide/security-access-control-privileges)) to describe it,
    regardless of whether the role holds MANAGE GRANTS or APPLY TAG ON ACCOUNT.

This change is being made to prevent roles from describing objects outside their intended access
scope through account-level administrative privileges.
