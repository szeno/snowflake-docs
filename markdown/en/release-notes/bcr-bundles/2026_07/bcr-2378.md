# Snowflake Cortex: CORTEX\_MODELS\_ALLOWLIST no longer controls model access (Pending)

Attention

This behavior change is in the 2026\_07 bundle.

For the current status of the bundle, refer to [Bundle history](/release-notes/bcr-bundles/2026_07_bundle#label-behavior-change-bundle-2026-07-status).

Access control based on the `CORTEX_MODELS_ALLOWLIST` account parameter is removed. Model role-based
access control (RBAC) becomes the only supported model access control mechanism for Snowflake AI,
and model RBAC is also enforced for embedding models.

This change is the enforcement phase of the
[CORTEX\_MODELS\_ALLOWLIST deprecation](/release-notes/bcr-bundles/un-bundled/bcr-2378), which was
announced as an unbundled behavior change.

Before the change:
:   Snowflake checked model RBAC first, then fell back to the `CORTEX_MODELS_ALLOWLIST` parameter.
    Access was allowed if either the calling role had access to the model object in `SNOWFLAKE.MODELS`
    or the model was covered by the allowlist. Model RBAC wasn’t enforced for embedding models.

After the change:
:   When the 2026\_07 behavior change bundle is enabled in your account, `CORTEX_MODELS_ALLOWLIST` isn’t
    consulted during authorization. Access is determined exclusively by model RBAC: the calling role
    must have access to the model through the corresponding model application role. Model RBAC is also
    enforced for embedding models, including [AI\_EMBED](/sql-reference/functions/ai_embed),
    [AI\_MULTI\_EMBED](/sql-reference/functions/ai_multi_embed),
    [AI\_SIMILARITY](/sql-reference/functions/ai_similarity),
    [EMBED\_TEXT\_768](/sql-reference/functions/embed_text-snowflake-cortex), and
    [EMBED\_TEXT\_1024](/sql-reference/functions/embed_text_1024-snowflake-cortex).

Model RBAC provides the same access outcomes the allowlist provided. An allowlist of `'All'` is
equivalent to granting `CORTEX-MODEL-ROLE-ALL` to the PUBLIC role, and an allowlist of specific
models is equivalent to granting those model application roles to PUBLIC. Accounts that grant
`CORTEX-MODEL-ROLE-ALL` also gain access to models Snowflake releases later, while accounts that
grant specific model roles must grant a new role for each new model.

## What you need to do

Before the bundle is enabled by default, confirm that the roles running your Cortex workloads have
the model application roles they need.

1. Check your current allowlist value. If it’s already `'None'`, your account uses model RBAC
   exclusively and no action is required.

   Copy code

   ```
   SHOW PARAMETERS LIKE 'CORTEX_MODELS_ALLOWLIST' IN ACCOUNT;
   ```
2. Review the model application roles granted to the PUBLIC role, and check for the automatic
   `CORTEX-MODEL-ROLE-ALL` bootstrap grant on `SNOWFLAKE.PUBLIC`. `SNOWFLAKE.PUBLIC` is an
   application role on the SNOWFLAKE database. It is not the same object as the account-level PUBLIC
   role, so `SHOW GRANTS TO ROLE PUBLIC` might not show the bootstrap path.

   Copy code

   ```
   SHOW GRANTS TO ROLE PUBLIC;
   SHOW GRANTS TO APPLICATION ROLE SNOWFLAKE.PUBLIC;
   ```

   If you receive the bootstrap grant and you want to restrict model access, don’t use a raw
   `REVOKE APPLICATION ROLE ... FROM ROLE PUBLIC` statement. That statement doesn’t remove the
   bootstrap grant from `SNOWFLAKE.PUBLIC`. Revoke or restore it with the stored procedures:

   Copy code

   ```
   CALL SNOWFLAKE.LOCAL.REVOKE_FROM_PUBLIC_APPLICATION_ROLE(
     'APP_ROLE',
     'CORTEX-MODEL-ROLE-ALL'
   );

   CALL SNOWFLAKE.LOCAL.GRANT_TO_PUBLIC_APPLICATION_ROLE(
     'APP_ROLE',
     'CORTEX-MODEL-ROLE-ALL'
   );
   ```

   For more context, see
   [Default bootstrap of CORTEX-MODEL-ROLE-ALL](/user-guide/snowflake-cortex/aisql-privileges-and-access#label-cortex-model-role-all-bootstrap).
3. Grant the equivalent model application roles for any models your workloads use, then set the
   allowlist to `'None'`. For the full procedure, see
   [Migrate from the allowlist to RBAC](/user-guide/snowflake-cortex/aisql-privileges-and-access#label-cortex-llm-migrate-to-rbac).

   Copy code

   ```
   ALTER ACCOUNT SET CORTEX_MODELS_ALLOWLIST = 'None';
   ```

Test in a non-production account first. Test with a role other than ACCOUNTADMIN, because
ACCOUNTADMIN always has access to all models.

Note

Restricted caller’s rights (RCR) stored procedures are an exception. Model RBAC doesn’t evaluate RCR
caller grants in RCR contexts, so granting model application roles to PUBLIC is sufficient for RCR
workloads.

This change is being made to standardize model access on a single, consistent authorization
mechanism, so that access follows the same role-based framework used elsewhere in Snowflake.

Note

Managed reader accounts without the `SNOWFLAKE.MODELS` schema continue to use
`CORTEX_MODELS_ALLOWLIST` during this migration.
