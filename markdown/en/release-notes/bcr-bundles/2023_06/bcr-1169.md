# TABLES views (Account Usage and Information Schema): TABLE\_TYPE column value shows correct value for event tables

Attention

This behavior change is in the 2023\_06 bundle.

For the current status of the bundle, refer to [Bundle History](/release-notes/bcr-bundles/2023_06_bundle#label-behavior-change-bundle-2023-06-status).

In the current Snowflake release, in the [Account Usage schema TABLES view](/sql-reference/account-usage/tables) and
[Information schema TABLES view](/sql-reference/info-schema/tables), the `TABLE_TYPE` column value have changed for certain rows.
When the table described in the view row is an [event table](/developer-guide/logging-tracing/event-table-columns), the
`TABLE_TYPE` column value will be `EVENT TABLE`.

Previously:
:   When the TABLES view row describes an event table, the row’s `TABLE_TYPE` column value is null.

Currently:
:   When the TABLES view row describes an event table, the row’s `TABLE_TYPE` column value is EVENT TABLE.
