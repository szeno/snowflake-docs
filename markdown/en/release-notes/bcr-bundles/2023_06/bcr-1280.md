# Task views and functions (Account Usage and Information Schema): ATTEMPT\_NUMBER value changed to 1-based

Attention

This behavior change is in the 2023\_06 bundle.

For the current status of the bundle, refer to [Bundle History](/release-notes/bcr-bundles/2023_06_bundle#label-behavior-change-bundle-2023-06-status).

The value of ATTEMPT\_NUMBER field in the following view behaves as follows:

- Account Usage views:

  - [COMPLETE\_TASK\_GRAPHS](/sql-reference/account-usage/complete_task_graphs)
  - [TASK\_HISTORY](/sql-reference/account-usage/task_history)
- Information Schema table functions:

  - [COMPLETE\_TASK\_GRAPHS](/sql-reference/functions/complete_task_graphs)
  - [CURRENT\_TASK\_GRAPHS](/sql-reference/functions/current_task_graphs)
  - [TASK\_HISTORY](/sql-reference/functions/task_history)

Previously:
:   The ATTEMPT\_NUMBER column is 0 based.
    For example, when the task/graph is run for the first time, the ATTEMPT\_NUMBER will be 0.
    If the task/graph is later retried, the ATTEMPT\_NUMBER will be 1, then 2, etc.

Currently:
:   The ATTEMPT\_NUMBER column will be 1 based.
    For example, when the task/graph is run for the first time, the ATTEMPT\_NUMBER will be 1.
    If the task/graph is later retried, the ATTEMPT\_NUMBER will be 2, then 3, etc.

Ref: 1280
