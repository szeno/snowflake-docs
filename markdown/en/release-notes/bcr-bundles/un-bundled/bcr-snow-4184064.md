# Schema-level data metric functions skip session temporary tables (Pending)

Note

The planned rollout date for this change is October 6, 2026 (Snowflake version 10.36). This announcement will be updated if the date
changes.

When you associate a data metric function (DMF) at the schema level, Snowflake no longer creates associations for
session temporary tables in that schema.

Before the change:
:   Associating a DMF with a schema created object-level associations for session temporary tables (`CREATE TEMPORARY TABLE`)
    in the schema, the same as for permanent tables. Temporary tables have domain `TABLE`, so they could not be omitted with
    `EXCLUDE_TABLE_TYPES`.

After the change:
:   Snowflake does not associate schema-level DMFs with session temporary tables. Those objects are skipped at attach time
    (when you add the DMF to the schema and when a new temporary table is created in the schema).

    Transient tables are still associated by default. To skip them, set `EXCLUDE_TABLE_TYPES = ('TRANSIENT')` on the
    schema-level association. `'TRANSIENT'` matches the table type that `SHOW TABLES` reports as `kind`, including tables
    created in a transient schema or database.

    Permanent staging tables that are neither temporary nor transient are not skipped by this change.

    For more information, see [Monitor the data quality of a schema](/user-guide/data-quality-schema-level).
