# Users with TYPE = SERVICE can authenticate with SAML SSO

Note

This change was rolled out with Snowflake version 10.31 (August 29 to September 2, 2026).

Users with their `TYPE` property set to `SERVICE` can authenticate with SAML single sign-on (SSO) through a
[SAML2 security integration](/user-guide/admin-security-fed-auth-security-integration).

Before the change:
:   Users with `TYPE = SERVICE` couldn’t log in using SAML SSO.

After the change:
:   Users with `TYPE = SERVICE` can log in using SAML SSO, including signing in to Snowsight and connecting through clients
    that use browser-based SSO. All other characteristics of `SERVICE` users are unchanged. For example, they still can’t
    log in using a password. For more information, see [Types of users](/user-guide/admin-user-management#label-user-management-types).

## Prevent SERVICE users from using SAML SSO

To keep `SERVICE` users from authenticating with SAML SSO, set an
[authentication policy](/user-guide/authentication-policies) that doesn’t include `SAML` in its
`AUTHENTICATION_METHODS` list. For example, to apply the policy to all `SERVICE` users in the account:

Copy code

```
CREATE AUTHENTICATION POLICY service_users_no_saml
  AUTHENTICATION_METHODS = ('KEYPAIR', 'OAUTH', 'PROGRAMMATIC_ACCESS_TOKEN', 'WORKLOAD_IDENTITY');

ALTER ACCOUNT SET AUTHENTICATION POLICY service_users_no_saml FOR ALL SERVICE USERS;
```

An authentication policy set on a specific user takes precedence over a policy set `FOR ALL SERVICE USERS`. If a
`SERVICE` user has its own authentication policy, make sure that policy doesn’t include `SAML` either. For more
information, see [ALTER ACCOUNT](/sql-reference/sql/alter-account).

To restore the previous behavior for all `SERVICE` users in an account, contact
[Snowflake Support](/user-guide/contacting-support).

Any future change to this behavior will be announced as a behavior change.
