# Account Usage: New and Changed Columns in Certain Views

Attention

This behavior change is in the 2023\_01 bundle.

For the current status of the bundle, refer to [Bundle History](/release-notes/bcr-bundles/2023_01_bundle#label-behavior-change-bundle-2023-01-status).

To differentiate between account-level roles and database roles, the following changes have been made to the specified Account Usage
views in the shared SNOWFLAKE database:

- New column, OWNER\_ROLE\_TYPE, has been added to the following views:

  - [FILE\_FORMATS](/sql-reference/account-usage/file_formats)
  - [FUNCTIONS](/sql-reference/account-usage/functions)
  - [MASKING\_POLICIES](/sql-reference/account-usage/masking_policies)
  - [PIPES](/sql-reference/account-usage/pipes)
  - [ROLES](/sql-reference/account-usage/roles)
  - [ROW\_ACCESS\_POLICIES](/sql-reference/account-usage/row_access_policies)
  - [SCHEMATA](/sql-reference/account-usage/schemata)
  - [SEQUENCES](/sql-reference/account-usage/sequences)
  - [STAGES](/sql-reference/account-usage/stages)
  - [TABLES](/sql-reference/account-usage/tables)
  - [TAGS](/sql-reference/account-usage/tags)
  - [VIEWS](/sql-reference/account-usage/views)

  The new column specifies the type of role (ROLE or DATABASE\_ROLE) that owns the object.
- [GRANTS\_TO\_ROLES](/sql-reference/account-usage/grants_to_roles) view:

  - Existing column, GRANTED\_TO, now differentiates between ROLE and DATABASE\_ROLE. Previously, it was always ROLE,
  - New column, GRANTED\_BY\_ROLE\_TYPE, that displays ROLE or DATABASE\_ROLE depending on whether the grantor is an account-level
    or database role.
- [QUERY\_HISTORY](/sql-reference/account-usage/query_history) view:

  - New column, ROLE\_TYPE, that displays ROLE or DATABASE\_ROLE depending on whether the job was executed by an account-level or
    database role.
