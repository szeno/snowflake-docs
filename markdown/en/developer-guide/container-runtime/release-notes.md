# Snowflake Container Runtime release notes

Starting with Container Runtime 3.0, these release notes expand coverage for changes in analytics, data engineering, and
machine learning packages, as well as [Notebooks in Workspaces](/user-guide/ui-snowsight/notebooks-in-workspaces/notebooks-in-workspaces-overview)
behaviors. For Container Runtime 2.10 and below, see
[Snowflake Container Runtime for machine learning release notes](/developer-guide/snowflake-ml/container-runtime/releases).

For details on Snowpark changes, see the [Snowpark Library for Python release notes](/release-notes/clients-drivers/snowpark-python).
For details on Snowflake ML API changes, see the [Snowflake ML Python release notes](/release-notes/clients-drivers/snowpark-ml).

Note

Releases are staged. Your Snowflake account might not update for a few days after the initial release date.

### Changes

**Added**

- Added Iceberg table support, including Azure Data Lake Storage locations, by preinstalling `pyiceberg` with its `adlfs` integration in CPU and GPU images.
- CPU and GPU images add a gated direct-Arrow display path for small pandas DataFrames. When enabled after coordinated frontend rollout, eligible frames can skip temporary-table and query-ID materialization. Larger frames and Snowpark DataFrames retain the existing path.

**Changed**

- Upgraded `snowflake-ml-python` from 1.54.0 to 2.5.0.
- Updated `polars` from 1.44.2 to 2.0.0.

**Fixed**

- Snowflake ML log and Prometheus directories are now created even when distributed ML Runtime startup is disabled, preventing missing-path logging failures.
- ML Jobs now ignore service-instance rows that have not yet been assigned an instance ID when resolving cluster topology.

### Notable package additions and removals

- Added `pyiceberg` 0.12.0 and `adlfs` 2026.8.0, plus the Azure identity and Blob Storage dependencies needed for Azure Iceberg table locations.
- Upgraded `polars` from 1.44.2 to 2.0.0.
- No notable top-level packages were removed.
